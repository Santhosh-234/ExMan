## OTA rule (learned the hard way)
- Updates only reach an installed APK whose runtimeVersion (policy: fingerprint) matches. The fingerprint includes `package.json` (dependencies AND scripts), app.json, `modules/`, assets. So do NOT edit package.json (even the `test` script) in a JS-only change; that silently orphans every installed build. Check before merging: `npx expo-updates fingerprint:generate --platform android | grep '"hash"'` should equal the last installed APK's value (Build 8 = 12bf9e92160841ce7f6cb39848471acdcf259acf; the native-release build (Build 12) = 038326b60123ae1419182c71db2e05ca611ecf8b). A new APK is only needed when that value must change. New tests go in src/utils/ (covered by the existing test glob).

## Working notes
- Android 13+: sideloaded apps need "Allow restricted settings" before Notification Access can be enabled.
- Native Kotlin was never compiled locally on the Mac (no JDK); CI was the first compile. `android/` is generated by `expo prebuild` and gitignored.
- Fast loop: `npx expo run:android` with the phone on USB (needs JDK 17 + Android SDK/NDK), JS changes hot reload; Kotlin changes rebuild incrementally. Use `adb logcat` to debug the receiver/listener.
- On Windows keep the repo path short and enable long paths (RN native builds hit the 260-char limit).
- Case-insensitive filesystem trap: don't create files differing only by case (`ingest.ts` vs `Ingest.tsx` broke tsc once).
